# 05b - 排版规范

> 状态：规划中 · 最后更新：2026-08-26
> 聚焦：排版拼版规则、图件布局、alpha 生成逻辑。
> 排版页面交互见 `05-页面与交互`（待补排版部分）；配置字段定义见 `02-配置文件规范` §4。

## 1. 概述

排版是把**多个图件**按预设拼到一张大画布上，输出一张**带透明 alpha 的平面 TIF**，供后道印刷上机。

- **输入**：图件来源二选一——从文件库选（通常是印前生成的 PSD 产物），或在排版页直接上传
- **输出**：普通 TIF（不分层，8bit sRGB + alpha），Classic TIFF 上限 4GB
- **解耦**：排版与印前生成相互独立，可只排版不生成，也可从文件库直接取已生成的印前图拼版

```
图件来源（文件库 / 新上传）──▶ 拼版（按 impose.json）──▶ 平面 TIF（带 alpha）──▶ 文件库
```

> 业务约束（spike 04/06 验证结论）：超大版面分层在 Python 环境无解（PSD 上限 30000px、PSB 分层无库支持），故排版输出**不分层**，靠 alpha 表达裁切区。详见 `03-整体架构` §3.3。

## 2. 业务场景

典型拼版场景（驱动字段设计，非穷举）：

| 场景 | 画布 | 图件 | 拼版 |
|------|------|------|------|
| **双幅床单拼版** | 260×200cm | 两张床单印前图 | 1×2 网格，水平并排 |
| **被罩AB面拼版** | 210×240cm | 被罩 A 面 + B 面 | 1×2 网格，B 面 180° 旋转 |
| **多件枕套拼版** | 150×100cm | 4 张枕套印前图 | 2×2 网格 |
| **长幅铺版** | 260×900cm | 多张图件纵向连排 | 1×N 网格 |

> 被罩 AB 面常需其中一面 180° 旋转（拉链方向对称）。本期仅支持旋转，不支持镜像——若业务必须镜像，需在印前阶段产出已镜像的图件后入库，再参与拼版（见 §13 开放问题 1）。

## 3. 拼版方式：原尺寸流式铺排

图件按**原始像素尺寸**（仅旋转，不缩放）行优先流式铺排：从画布左上角 (0,0) 开始，沿 x 方向依次摆放；当前行剩余宽度放不下下一张时换行（y 累加当前行最大高度）。无间距、无边距、无网格槽位。

```
画布
┌──────────────────────────┐
│ ┌────────┬───────┐       │
│ │  图件A  │  图件B │       │  ← row 0（A 宽 + B 宽 ≤ 画布宽）
│ ├────────┴───────┼───────┤
│ │     图件C      │ 图件D │  ← row 1（B 放不下换行）
│ └────────────────┴───────┘
└──────────────────────────┘
```

### 3.1 放置规则

- 图件**不缩放、不拉伸**，只按 `rotation` 旋转后用实际像素尺寸摆放
- 起点 (0,0)，沿 x 累加；`x + 图件宽 > 画布宽` 且 `x > 0` 时换行（`y += 当前行最大高`，`x = 0`）
- 无 margin/gap，图件紧贴排列
- **超出报错**：任一图件（含旋转后）放置后超出画布右/下边界，任务失败

### 3.2 图件顺序

`slots` 列表顺序即铺排顺序（行优先）。无空槽、无网格行列数概念。

> 旧版网格拼版（rows×cols 等分槽位 + fit_mode 适配）已废弃，改为原尺寸流式铺排。预设基础设施保留但工作流页不再使用。

## 4. 图件来源与映射

### 4.1 来源二选一

- **文件库选图**：从 `library.db` 的 `images` 表选 `source=prepress`（或 `source=upload`）的图件
- **新上传**：排版页直接上传图件，上传即入库（`source=upload`），再参与拼版

> 两种来源在拼版阶段无差别，统一按 image_id 引用。

### 4.2 提交映射

提交排版任务时，`slots` 用 image_id 引用图件：

```json
{
  "preset_id": "double_bedsheet",
  "slots": [
    {"image_id": "01JX…", "rotation": 0},
    {"image_id": "01JY…", "rotation": 180}
  ]
}
```

- `image_id`：文件库中的图片 id（ULID）
- `rotation`：图件旋转角度（见 §5）

## 5. 图件变换（仅旋转）

本期仅支持 **90° 倍数旋转**，不支持镜像。

| 字段 | 类型 | 默认 | 说明 |
|------|------|------|------|
| `rotation` | int | 0 | 旋转角度，∈ {0, 90, 180, 270}，顺时针 |

### 5.1 旋转规则

- 90°/270° 旋转后图件宽高互换，用旋转后尺寸参与流式铺排
- **alpha 跟随旋转**：图件透明区旋转后仍是透明区
- 图件不缩放，旋转后仍按原始像素尺寸摆放

### 5.2 fit_mode（已废弃）

原尺寸流式铺排模式下**不缩放图件**，无 fit_mode。旧网格模式的 stretch/contain/cover 已移除。

## 6. 间距与咬口（gutters）

| 字段 | 类型 | 默认 | 说明 |
|------|------|------|------|
| `horizontal_mm` | float | 0 | 槽位间水平间距 |
| `vertical_mm`   | float | 0 | 槽位间垂直间距 |
| `margin_mm`     | float | 0 | 画布四周留白 |

- 间距区与留白区 alpha=0（要被裁切掉的部分，见 §8）
- 印刷咬口位（机器夹口）通常预留 10–20mm，用 `margin_mm` 表达
- 间距非零时，相邻图件之间有裁切缝 + 裁切线（见 §7）

## 7. 标记（marks）

复用印前标记语义，但排版阶段**所有标记画在 alpha=255 的图件区附近**，不画在透明区。

| 字段 | 类型 | 默认 | 说明 |
|------|------|------|------|
| `crop_marks` | bool | true | 裁切线，画在每个槽位四角 |
| `crop_mark_length_mm` | float | 5 | 裁切线长度 |
| `crop_mark_offset_mm` | float | 3 | 裁切线距图件边偏移 |
| `registration_marks` | bool | false | 套准标记（画布四角十字标） |

### 7.1 裁切线位置

- 每个槽位四角各画 2 条裁切线（L 形），共 8 条/槽位
- 偏移方向：朝槽位外侧
- 相邻槽位共享的裁切线不重复绘制（避免重叠）

### 7.2 套准标记

- 画布四角各一个十字标
- 用于多色印刷对版
- 标记本身 alpha=255（实色），位于画布 margin 内

## 8. alpha 生成逻辑（核心）

排版输出的 TIF **必须带 alpha 通道**，alpha 语义见 `02-配置文件规范` §4.3：**透明区 = 要被裁切掉的区域**。

### 8.1 alpha 规则

| 区域 | alpha | 说明 |
|------|-------|------|
| 图件区（slot 内 fit_mode 覆盖部分） | 255 | 保留成品 |
| `contain` 留白区 | 0 | 图件未覆盖的槽位部分，裁掉 |
| `gutters` 间距区 | 0 | 槽位之间，裁掉 |
| `margin` 留白区 | 0 | 画布边缘，裁掉（含咬口位） |
| 空槽位（slot=null） | 0 | 整格透明 |
| 裁切线/套准标记像素 | 255 | 标记本身实色 |

### 8.2 生成顺序

```
1. 创建画布 pyvips.Image，尺寸 = canvas 像素，4 通道 RGBA，全透明 (alpha=0)
2. 逐槽位合成：
   a. 载入图件（从文件库或上传图）
   b. 按 rotation 旋转
   c. 按 fit_mode 适配到槽位尺寸
   d. 计算槽位在画布上的像素偏移
   e. composite "over" 到画布（图件 alpha=255 区域覆盖画布透明区）
3. 绘制标记层（裁切线、套准标记），alpha=255
4. 整张 colourspace("srgb").cast("uchar")，写普通 TIF
```

> 关键技术点（spike 06 验证）：写 TIF 前必须 `.colourspace("srgb").cast("uchar")` 强制 8 位 sRGB，并加 `bitdepth=8`，否则 pyvips 可能存成 32 位浮点 scRGB，Photoshop 报"不受支持的位深度"。详见 `CLAUDE.md` §3 技术栈约束。

## 9. 输出

### 9.1 输出格式

- **普通 TIF**（Classic TIFF），不分层，带 alpha
- 8bit sRGB + alpha（4 通道）
- 压缩：`deflate`（默认）
- DPI 写入 TIF 元数据（`xres` / `yres`，单位 inch）

### 9.2 尺寸边界

| 边界 | 阈值 | 处理 |
|------|------|------|
| 画布像素 ≤ 30000×30000 | PSD 上限 | 本期不涉及（排版出 TIF，不出 PSD） |
| 文件 ≤ 4GB | Classic TIFF 上限 | 正常输出 |
| 文件 > 4GB | 超 Classic TIFF | 报错，提示改 `bigtiff`（16bit 大画布时触发） |

> 260×900cm@150dpi RGB8+alpha ≈ 3.26GB，在 Classic TIFF 4GB 上限内（spike 04/06 验证）。16bit 同尺寸 ≈ 6.5GB，超限，须降级 bigtiff。

### 9.3 写入文件库

- 输出到 `data/library/images/{id}/original.tif`（见 `07-文件存储`）
- `source=impose`，关联 `preset_id` 与 `task_id`
- 同时生成缩略图 `thumb.webp`（Pillow，对 alpha 做白底合成再缩略）

## 10. 页面交互要点（已实现 · 原尺寸流式铺排）

详细交互见 `05-页面与交互` §9。本文档只列与拼版规则强相关的要点：

1. **图件列表**：左侧添加若干图件（上传/文件库多选），按列表顺序行优先流式铺排
   - 每图件支持 `rotation` 选择（0/90/180/270）
   - 可调顺序（上移/下移）、删除
   - 图件**不缩放**，只旋转，按原始尺寸摆放
2. **内联配置**：右侧填画布宽高/DPI/保存名，无预设、无列数、无间距边距
3. **预览画布**：中间 Canvas 实时按比例绘制图件缩略图 + 边距/间隔线 + 透明区棋盘格
4. **标记**：不画裁切线/套准标记
5. **提交**：操作员确认后提交到任务队列，后台生成最终 TIF；任一图件超出画布则失败

> 排版预览与印前生成预览共用缩略图规格（见 `07-文件存储` §4）。
> 预设基础设施（impose.json / 只读配置页）保留，但工作流页不再使用预设。

## 11. 配置字段（回写 `02-配置文件规范` §4）

`impose.json` 的 `presets` 在原字段（canvas/gutters/marks/output）基础上新增 `layout`：

### 11.1 新增字段：layout

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `mode` | string | 是 | 拼版方式，本期仅 `grid` |
| `rows` | int | 是 | 网格行数（≥1） |
| `cols` | int | 是 | 网格列数（≥1） |
| `default_fit_mode` | string | 否 | 槽位默认 fit_mode，默认 `stretch` |

### 11.2 完整 preset 结构

```json
{
  "id": "double_bedsheet",
  "name": "双幅床单拼版",
  "canvas": {
    "width_mm": 2600,
    "height_mm": 2000,
    "dpi": 150,
    "bitdepth": 8
  },
  "layout": {
    "mode": "grid",
    "rows": 1,
    "cols": 2,
    "default_fit_mode": "stretch"
  },
  "gutters": {
    "horizontal_mm": 10,
    "vertical_mm": 0,
    "margin_mm": 20
  },
  "marks": {
    "crop_marks": true,
    "crop_mark_length_mm": 5,
    "crop_mark_offset_mm": 3,
    "registration_marks": false
  },
  "output": {
    "format": "tif",
    "compression": "deflate",
    "color_profile": "srgb"
  }
}
```

### 11.3 校验规则（追加到 `02` §4.5）

- `layout.mode` ∈ {`grid`}（本期仅一种）
- `layout.rows` / `layout.cols` ≥ 1，整数
- `layout.default_fit_mode` ∈ {`stretch`, `contain`, `cover`}
- `slots` 长度（提交时）= `rows * cols`，可含 `null`
- 槽位 `rotation` ∈ {0, 90, 180, 270}

## 12. 任务流水线（与 `06` 对接）

排版任务的进度阶段（回写 `06` §3.3 排版阶段）：

| 阶段 | 进度区间 | 说明 |
|------|---------|------|
| 载入图件 | 0-30 | 从文件库/上传图载入所有 slots 的图件 |
| 拼版合成（带 alpha） | 30-80 | 逐槽位旋转、适配、composite 到画布 |
| 标记 | 80-90 | 裁切线、套准标记 |
| 写 TIF | 90-100 | colourspace + cast + tiffsave |

## 13. 开放问题

1. **镜像支持**：被罩 AB 面若业务必须镜像（非旋转可解决），是延后做，还是在印前阶段产出已镜像图件？
2. **自由拼版**：本期仅网格，未来是否扩展 `free`（每图件独立 x/y）？触发条件待定
3. **图件重复**：同一 image_id 放多个槽位时，是否需要在配置层显式声明，还是提交时自由引用？
4. **裁切线去重**：相邻槽位共享裁切线的去重逻辑，按像素重叠消除还是按方向判断？（本期引擎不去重，重叠重绘无害）
5. **咬口方向**：`margin_mm` 四周一致，实际印刷咬口只在某一侧，是否需要分边配置？
6. **16bit 大画布**：超 4GB 降级 bigtiff 的自动判定与提示策略
7. **排版预览性能**：大画布（260×900cm）定比缩略图在前端合成还是后端接口？前端 Canvas 可能吃力（本期不做实时预览，最终预览靠任务完成返回的缩略图）
8. **大画布标记内存**：pyvips `draw_line` 画标记需随机写访问，会在写 TIF 前把整画布实体化进内存（260×900cm@150dpi RGBA8 ≈ 3.26GB）。超大画布可改用"小线段图 insert 进惰性画布"的流式方案，本期未实现
9. **引擎与存储解耦**：排版引擎 `run()` 接收**已解析的文件路径**槽位与 `Preset` 对象，不依赖文件库/image_id；image_id→路径解析在 web 层（与印前 `run` 接收 image_path 一致）。任务接入/API/页面待后续
