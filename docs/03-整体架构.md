# 03 - 整体架构

> 状态：规划中 · 最后更新：2026-08-25

## 1. 架构总览

**形态**：Web 应用，前后端不分离。FastAPI 进程同时承担页面渲染与接口，模板由服务端返回，前端只做交互逻辑。

**两大独立功能**：
- **印前生成**：上传图 → 选类型尺码 → 按配置生成分层印前文件 → 直接入文件库
- **排版**：从文件库选图或新上传 → 按排版配置拼版 → 输出印刷文件

```
┌─────────────────────────────────────────────────────────────┐
│                           浏览器                              │
│   印前生成页        排版页           文件库页                  │
│   上传·选型·选码    选库/上传·选配置   全缩略图浏览·下载        │
└──────────────────────────┬──────────────────────────────────┘

┌──────────────────────────▼──────────────────────────────────┐
```

## 2. 技术栈

| 层 | 选型 | 说明 |
|----|------|------|
| **语言** | Python 3.10+ | 生态成熟，图像库齐全 |
| **Web 框架** | FastAPI | 页面渲染 + API 同进程，异步支持好 |
| **模板** | Jinja2 | 服务端渲染，前后端不分离 |
| **任务队列** | 线程池 + 插件式脚本（ThreadPoolExecutor） | 生成与排版耗时长，需异步 + 进度反馈；pyvips 是 C 扩展释放 GIL，线程池真并行 |
| **实时推送** | WebSocket | 任务进度长连接推送，前端不轮询 |
| **持久化** | SQLite | 任务记录、任务日志落盘，进程重启队列保留 |
| **配置** | JSON 文件 | 印前配置树 + 排版配置，各自独立 |
| **部署** | **Docker 容器** | libvips 等系统依赖打进镜像，环境一致 |

## 3. 图像处理内核（核心选型）

> 场景特点：图片尺寸大、DPI ≥ 150、全部输出分层、TIF 优先并支持 PSB、含排版功能。
> Pillow 在大图与高位深下吃力，**以 pyvips 为主力引擎**。

### 3.1 库职责划分

| 库 | 职责 | 选用理由 |
|----|------|----------|
| **pyvips** | 主引擎：几何变换、色彩管理、大图处理、TIF/PSB 位图输出 | 流式处理、内存占用低、原生 16-bit + ICC、印刷流水线常用 |
| **psd-tools** | PSD/PSB 分层组装 | 支持分层结构读写，满足全输出分层需求 |
| **Pillow** | 缩略图生成、PNG 预览 | 网页缩略图与预览用，不扛大图主力 |
| **OpenCV** | 不纳入主链路 | 仅将来 QC 预检可用，只读分析 |

### 3.2 为什么 pyvips 当主力

- **大图友好**：流式/分块处理，几 GB 的图稳定跑，不像 Pillow 整张载入内存
- **高位深 + ICC**：原生支持 16-bit TIF、ICC Profile 色彩转换
- **性能**：C 实现，多线程，单机吞吐高

### 3.3 输出策略（分场景）

> **spike 验证结论（2026-08-25/26）**：
> - psd-tools 能写 **PSD 分层**（图层名限 ASCII），PSD 尺寸上限 30000×30000px
> - pyvips 写**普通 TIF**（带 alpha，验证通过），Classic TIFF 上限 4GB
> - 大尺寸分层在 Python 服务器环境无法实现（PSD 超尺寸，PSB 分层无库支持）
> - 260×900cm@150dpi RGB8+alpha ≈ 3.26GB，在普通 TIF 4GB 上限内
>
> 详见 `spike/01~06`。

**按场景区分**（最终方案）：

| 场景 | 输出 | 分层 | 格式 | 主责库 |
|------|------|------|------|--------|
| **印前生成**（单产品，尺寸小） | 分层文件 | ✅ 分层 | **PSD** | psd-tools |
| **排版输出**（超大版面） | 带透明 alpha 的平面 | ❌ 不分层 | **普通 TIF** | pyvips |

- **印前生成**：图案层+标记层等分层存 **PSD**（后道微调）
- **排版输出**：超大版面不分层，**保留透明 alpha 通道**，输出**普通 TIF**（通用性好，Photoshop/RIP 均可打开）
- **边界**：8bit 适用。若需 16bit，大尺寸 4 通道 ≈ 6.5GB 超 4GB 上限，须降级为 bigtiff

### 3.4 缩略图策略

- **网页展示全部用缩略图**：文件库、生成结果、排版输入预览均展示缩略图，原图不直接进页面
- 缩略图由 Pillow 在文件入库时生成，与原图一同落盘
- 缩略图规格（尺寸/质量）统一，见 `07-文件存储`

## 4. 两大独立功能

### 4.1 印前生成

```
上传图 ──▶ 预检 ──▶ 生成（裁放/出血/分层） ──▶ 输出分层文件 ──▶ 入文件库
         (格式/尺寸/   (按印前配置)           (TIF优先/PSB)     (原图+缩略图)
          分辨率检查)
```

- 读取**印前配置树**（类型→尺码→参数）
- 生成结果**直接进入文件库**，不经过排版
- 入库时同时生成缩略图

### 4.2 排版

```
选图来源 ──▶ 排版（拼版/咬口/裁切标记） ──▶ 输出印刷文件
 (文件库 或    (按排版配置)               (分层 TIF/PSB)
  新上传)
```

- 读取**独立的排版配置**（拼版幅面、咬口尺寸、排版方式等，与印前配置分离）
- **输入来源二选一**：从文件库选已生成的印前图，或在排版页直接上传
- 排版输出同样分层，TIF 优先，支持 PSB

> 生成与排版解耦：可只生成不入库后排版，也可跳过生成直接上传排版。两者各自独立的页面与配置。

## 5. 文件库

- **统一存储**：印前生成结果统一入文件库，原图与缩略图成对存放
- **网页浏览**：文件库页面**全部以缩略图展示**，保证大图场景下的页面性能
- **排版取用**：排版页可从文件库选图，也可独立上传
- 命名、归档、清理策略见 `07-文件存储`

## 6. 模块划分

```
app/
├── web/                # 页面与接口
│   ├── routes/         # 上传、生成、排版、文件库、下载
│   └── templates/      # Jinja2 页面
├── config/             # 配置加载与校验（读取 configs/ 下的 json）
│   ├── prepress.py     # 印前配置树（读取 configs/prepress/）
│   ├── impose.py       # 排版配置（读取 configs/impose/）
│   └── storage.py      # 存储配置（读取 configs/storage/）
├── engine/             # 图像处理内核
│   ├── preflight.py    # 预检
│   ├── generate.py     # 印前生成（分层输出）
│   ├── impose.py       # 排版
│   └── thumbnail.py    # 缩略图生成
├── tasks/              # 任务调度（插件式调度器，详见 06）
│   ├── scheduler.py    # 调度器：队列、Worker 线程池、注册表、生命周期
│   ├── base.py         # BaseTask 基类 + TaskContext + Signal
│   ├── registry.py     # 任务类型注册与发现（importlib 扫描 scripts/）
│   ├── scripts/        # 任务脚本目录（每类一个 .py，插件式扩展）
│   │   ├── prepress.py # 印前生成任务
│   │   └── impose.py   # 排版任务
│   ├── ws.py           # WebSocket 推送（signal → 前端）
│   └── logger.py       # 任务级日志辅助
└── storage/            # 文件库 + 任务记录
    ├── store.py        # 原图+缩略图落盘、命名、检索、清理
    └── db.py           # 任务记录与日志持久化（SQLite）
```

| 模块 | 职责 |
|------|------|
| **web** | 页面渲染 + API：印前生成页、排版页、文件库页、上传/下载/进度 |
| **config** | 分别加载印前配置树与排版配置，校验并提供查询 |
| **engine** | 预检、生成、排版、缩略图四个子模块 |
| **tasks** | 插件式调度器：调度器只管分配/状态收集/推送，每种任务是一个继承 BaseTask 的 Python 类放 `scripts/` 下，importlib 动态加载；新增任务类型不改调度器；WebSocket 推送进度；任务持久化重启保留；任务级日志 |
| **storage** | 文件库（原图+缩略图）+ 任务记录/日志 DB（SQLite） |

## 7. 部署形态（Docker）

- **Docker 容器部署**：FastAPI + libvips + psd-tools 等全部依赖打进镜像
- 基础镜像选 Python 官方镜像，通过 apt 安装 libvips 系统依赖
- 本地开发时，libvips 等外部依赖统一放在 `vendor/` 目录管理（见 `CLAUDE.md` 3a）
- 文件库通过**卷挂载（volume）**持久化，容器重建不丢数据
- 单容器即可运行；后续若拆任务队列，再考虑多容器编排
- Dockerfile 与 compose 配置见 `08-部署与运维`

## 8. 开放问题

1. **任务队列选型**：已定——线程池 + 插件式脚本（详见 `06`），单机 Docker 无外部依赖；未来多机扩展再引入 Celery + Redis
2. **进度反馈机制**：WebSocket 长连接实时推送任务进度，前端不轮询（见 `06-任务处理引擎` §4）
3. **并发与排队**：大图处理耗资源，单容器并发上限与排队策略（见 `06`）
4. **缩略图规格**：统一尺寸/质量如何定？是否按用途分多档
5. **文件库检索**：是否需要按类型/尺码/时间筛选与搜索
6. **图层命名**：psd-tools 图层名限 ASCII，业务层名需用英文/代号，规则待定
7. **排版 alpha 语义**：已定稿——透明区 = 裁切掉的区域（见 `02-配置文件规范` 4.3）
