# 01 - 需求与目标

> 状态：规划中 · 最后更新：2026-08-25

## 1. 业务背景

床上用品（家纺）印刷生产中，设计方交付的图片稿件需要按**产品类型**和**尺码规格**转换成符合上机印刷标准的印前文件。不同类型（床单、床笠、被罩 A/B 面、枕套等）、不同尺码对应不同的排版参数（成品尺寸、出血、分辨率、分层等）。

目前这一步常由人工在 Photoshop 中逐个处理，效率低、易出错、规格难统一。本项目用一套**配置驱动**的 Web 服务替代人工：上传图 → 选类型 → 选尺码 → 自动出印前文件。

## 2. 项目目标

### 2.1 核心目标

| # | 目标 | 说明 |
|---|------|------|
| G1 | **配置化驱动** | 产品类型与尺码通过配置文件定义，增删规格不改代码 |
| G2 | **一键生成** | 上传图片 + 选择类型尺码，自动产出印前文件 |
| G3 | **多格式输出** | 支持 PSD / TIF / PNG，可单格式或多格式同时输出 |
| G4 | **Web 化操作** | 浏览器即用，无需安装客户端，前后端不分离 |

### 2.2 非目标（本期不做）

- 不做多人协同 / 工单流转 / 审批流程
- 不做用户体系与多租户（单机/单团队使用为主）
- 不做与 RIP / 印刷设备的直接对接（只产出文件，交付由人完成）
- 不做在线编辑器（不替代 Photoshop 的设计能力）

> 后续若有需要，上述可作为演进方向，不影响当前架构主干。

## 3. 用户角色

| 角色 | 描述 | 主要操作 |
|------|------|----------|
| **操作员** | 日常使用本服务生成印前文件 | 上传图、选类型尺码、下载结果 |
| **配置管理员** | 维护产品类型与尺码配置 | 编辑配置文件、增删规格 |

> 本期两类角色暂不通过账号区分，配置由文件管理；后续可加权限层。

## 4. 功能需求

### 4.1 配置管理

- F1.1 系统启动时加载预设配置文件
- F1.2 配置为两级树：**类型 → 尺码**
- F1.3 每个尺码节点挂载该规格的印前参数（尺寸/出血/DPI/分层/输出格式等）
- F1.4 支持热更新或重启生效（二选一，待定，见 [开放问题](#7-开放问题)）

### 4.2 文件上传

- F2.1 支持常见位图格式上传（PNG / JPG / TIFF / PSD 等具体范围待定）
- F2.2 支持大文件上传（断点续传是否需要，见 [开放问题](#7-开放问题)）
- F2.3 上传后保留原图，处理基于副本

### 4.3 类型与尺码选择

- F3.1 页面展示配置树第一级（类型列表）
- F3.2 选中类型后，展示该类型下的尺码列表
- F3.3 尺码选中后，可触发生成

### 4.4 印前文件生成

- F4.1 按选中尺码的配置参数处理上传图
- F4.2 输出 PSD / TIF / PNG，格式由配置决定，可多格式同时输出
- F4.3 PSD 保留印前分层（图案层 / 标记层等，分层规则见 `04-预检与生成参数`）
- F4.4 处理过程异步，页面可查看进度/状态
- F4.5 失败可重试，给出失败原因

### 4.5 结果下载

- F5.1 处理完成后提供下载链接
- F5.2 多格式输出时分别提供下载
- F5.3 文件命名规则统一（见 `07-文件存储`）

## 5. 非功能需求

| 类别 | 要求 |
|------|------|
| **易用性** | 单页面完成全流程，操作步骤 ≤ 5 步 |
| **响应性** | 上传与生成过程有明确进度反馈，不长时间无响应 |
| **可维护性** | 规格变更只改配置文件，不改动代码 |
| **可移植性** | 可在 Windows / Linux 部署，依赖可控 |
| **性能** | 单张图片常规尺码生成应在合理时间内完成（具体指标待定） |
| **可靠性** | 处理失败不丢原图，可重试；异常有日志 |

## 6. 约束与假设

- 输出以**位图**为主（PSD/TIF/PNG），不涉及矢量排版
- 印前参数（尺寸、出血、DPI 等）由业务方提供，本系统按配置执行，不自行推断
- 处理质量依赖原图质量；原图不达标时给出提示，但不强制阻断（策略待定）

## 7. 开放问题

待与业务方确认后定稿：

1. **配置热更新**：改配置文件后是热加载生效，还是需重启服务？
2. **上传格式范围**：输入图明确支持哪几种？（PNG/JPG/TIFF/PSD？）
3. **大文件上传**：是否需要断点续传？最大文件多大？
4. **原图不达标处理**：分辨率不足等情况下，是阻断、警告还是按配置强行生成？
5. **并发处理**：是否需要支持多人同时提交任务？任务排队策略？
6. **文件保留期**：生成文件在服务器保留多久？是否自动清理？
7. **输出分层细节**：PSD 的分层结构具体要求（哪些层、层命名）？

> 这些问题不影响当前架构主干，但会影响 `02-配置文件规范` 与 `06-任务处理引擎` 的细节，需尽早确认。
