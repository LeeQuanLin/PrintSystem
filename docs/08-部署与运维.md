# 08 - 部署与运维

> 状态：规划中 · 最后更新：2026-08-26

## 1. 部署形态

- **Docker 容器部署**：FastAPI + libvips + psd-tools + 所有 Python 依赖打进镜像
- **单容器即可运行**：Web 服务 + 任务 Worker + WebSocket 同进程
- 文件库通过 **volume 映射**持久化，容器重建不丢数据
- 部署目标：Linux 服务器为主（Windows 亦可，libvips 依赖处理方式不同）

## 2. Docker 镜像

### 2.1 基础镜像

- `python:3.11-slim`（Linux 部署）
- libvips 通过 apt 安装系统级依赖

### 2.2 Dockerfile（雏形）

```dockerfile
FROM python:3.11-slim

# 系统依赖：libvips 及其运行时
RUN apt-get update && apt-get install -y --no-install-recommends \
    libvips libvips-tools \
    && rm -rf /var/lib/apt/lists/*

WORKDIR /app

# Python 依赖（利用层缓存）
COPY pyproject.toml uv.lock ./
RUN pip install uv && uv sync --frozen --no-dev

# 应用代码
COPY app/ ./app/
COPY configs/ ./configs/

EXPOSE 8000

# 启动：Web + Worker 同进程（uvicorn + 后台线程池）
CMD ["uv", "run", "uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

> libvips 版本以 Debian/Ubuntu 仓库版本为准；若需特定版本，可改用源码编译或预编译包。

### 2.3 Windows 部署

- 本地开发用 `vendor/libvips/` 预编译包（见 `CLAUDE.md` 3a），通过 `add_dll_directory` 加载
- 生产部署优先 Linux Docker；若必须 Windows，镜像内放置 libvips 预编译包并设置 PATH

## 3. 数据持久化（volume 映射）

| 容器路径 | 宿主机映射 | 内容 | 持久化 |
|---------|-----------|------|--------|
| `/app/data/library` | `./data/library` | 文件库（图片 + SQLite） | ✅ volume |
| `/app/configs` | `./configs` | 配置文件（按模块分文件夹） | ✅ volume |
| `/app/logs` | `./logs` | 系统日志 | ✅ volume |

```json
# docker-compose.yml（雏形）
services:
  prepress:
    build: .
    ports:
      - "8000:8000"
    volumes:
      - ./data/library:/app/data/library    # 文件库 + SQLite
      - ./configs:/app/configs              # 配置文件（按模块分文件夹）
      - ./logs:/app/logs                    # 日志
    restart: unless-stopped
```

- `data/library/` 整体映射：图片文件（`images/{id}/`）与 `library.db` 一同持久化
- 任务队列重启保留：SQLite 中的 `tasks` 表，启动时加载未完成任务（见 `06` §5）

## 4. 日志

### 4.1 两层日志（见 `06` §9）

| 层级 | 存储 | 用途 |
|------|------|------|
| 任务级 | SQLite `task_logs` 表 | 页面任务详情查看处理链路 |
| 系统级 | `logs/app.log` 文件 | 运维排查 |

### 4.2 系统日志滚动

- 按日滚动（`RotatingFileHandler` 或 `TimedRotatingFileHandler`）
- 保留天数可配置（默认 30 天）
- 失败任务 ERROR 与任务 `error` 字段关联

### 4.3 日志目录

- 容器内 `/app/logs/`，映射到宿主机 `./logs/`
- 与文件库 volume 分开，便于独立备份/清理

## 5. SQLite 运维

- 单文件 `data/library/library.db`，含 `images` / `tasks` / `task_logs` 三表
- 无需独立数据库服务，单机 Docker 友好
- 并发写：SQLite WAL 模式，支持读写并发（任务 Worker 写、Web 读）
- 备份：直接复制 `library.db` 文件（或 `.backup` 命令）

## 6. 配置管理

- 三套配置文件（见 `02-配置文件规范`），按模块分文件夹存放在 `configs/`：
  - `configs/prepress/prepress.json` — 印前配置树
  - `configs/impose/impose.json` — 排版配置
  - `configs/storage/storage.json` — 存储与缩略图规格
- 通过 volume 映射，**改配置无需重建镜像**，重启容器即可生效
- 热更新待定（见 `02` 开放问题 1）

## 7. 监控与运维

| 项 | 方式 |
|----|------|
| 任务状态 | 页面任务面板（WebSocket 实时） |
| 进程健康 | `/health` 接口 |
| 系统日志 | `logs/app.log` |
| 任务日志 | 页面任务详情 + DB 查询 |
| 资源占用 | Docker stats（内存/CPU） |

> 大图处理耗内存，监控 Worker 内存占用，必要时调低并发上限（`06` §3.2）。

## 9. 开放问题

1. **Worker 与 Web 是否拆分**：当前同进程（线程池），未来若资源压力大是否拆为独立容器（Worker 单独扩缩容）？
2. **libvips 版本固定**：apt 版本较旧时，是否改用源码编译或预编译包固定版本？
3. **日志保留期**：`logs/` 与 `task_logs` 表的保留天数待定
4. **备份策略**：`library.db` 与图片文件的备份频率与方式
5. **HTTPS**：是否在容器前置反向代理（nginx/caddy）处理 TLS
